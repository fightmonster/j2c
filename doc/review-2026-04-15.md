# jira2claw CLI 综合评审报告

> 评审日期: 2026-04-15 | 版本: 1.1.3 | 方式: Agent Team 三维度并行评审

## 一、日常使用 & UX

### 优点
| 项 | 说明 |
|---|---|
| 命令覆盖全面 | read/view/list/comment/status/assign/download/batch/projects/me 等，日常 Jira 操作基本覆盖 |
| 双别名设计 | `read`(默认md) 给 AI，`view`(默认table) 给人，场景区分清晰 |
| 批量操作安全 | `--dry-run` 预览 + 二次确认 + `--yes` 免确认，防止误操作 |
| 非交互模式 | `--pat/--cf-client-id/--cf-client-secret` 一行配置，CI/CD 友好 |
| 多格式输出 | table/json/md/csv 四种格式，适配不同消费方 |
| JQL 直通 | `-j` 参数支持任意 JQL，灵活度高 |
| 非TTY自动禁色 | 管道/日志无 ANSI 污染 |
| 文档完善 | README 快速入门 + docs/ 详细参考，JQL 示例丰富 |

### 缺点
| 项 | 影响 | 优先级 |
|---|---|---|
| **缺少 `create` 命令** | 无法通过 CLI 创建 Issue，日常高频操作缺失 | P0 |
| **每次执行都验证登录** | checkConnection + getMyself 两次 HTTP，额外 200-500ms | P0 |
| **缺少 shell 补全** | 无 bash/zsh completion，体验远低于 gh | P1 |
| **`me` 命令无 JSON 输出** | AI 场景不便 | P1 |
| **`projects` 未入文档** | README 和 docs 未更新 | P1 |
| **无 `--quiet` 模式** | CI 场景 stderr 日志冗余 | P2 |
| **批量操作无进度条** | 大批量执行时无反馈 | P2 |
| **无 pager 支持** | 长输出无分页 | P2 |
| **评论命令冗长** | `list-comments/edit-comment/delete-comment` 可合并为 `comment list/edit/delete` | P2 |

## 二、架构 & 代码质量

### 优点
| 项 | 说明 |
|---|---|
| 分层清晰 | `cli/commands` → `client` → `config`，职责明确 |
| TypeScript 全覆盖 | 所有源码 .ts，有类型定义 |
| 配置管理统一 | config.ts 集中管理环境变量和文件配置，优先级清晰 |
| Commander.js 选型合适 | 轻量、生态好、help 自定义完善 |

### 缺点
| 项 | 位置 | 优先级 |
|---|---|---|
| **`any` 泛滥** | jira-client.ts ~20+ 处 `(res: any)`，丧失类型安全 | P1 |
| **http 请求方式不统一** | 部分用 jira.js SDK，部分手动 https.request，维护成本高 | P0 |
| **重复请求模式** | getFields/getProjects/getProjectIssueCounts 结构几乎一致，应抽取通用方法 | P0 |
| **`import('https')` 动态导入** | 每个方法都 `await import('https')`，应顶部静态 import | P1 |
| **cf-middleware.ts 角色退化** | 改直传 headers 后只剩 re-export + 2 个检测函数，可合并到 config.ts | P1 |
| **`ws` 依赖残留** | CDP 时代遗留，不再需要 | P1 |
| **new URL() 重复创建** | 构造函数中已解析 host，但每个方法又 new 一次 | P2 |

## 三、性能 & 可靠性

### 优点
| 项 | 量化 |
|---|---|
| 批量并发控制 | concurrency=5，防止连接池耗尽 |
| 统一 10s 超时 | 防止请求永久挂起 |
| CF Token 直传 | 比旧 cookie 方案少一次网络往返 |
| 网络重试 | ECONNRESET/ETIMEDOUT 重试一次，约 30% 偶发错误可恢复 |

### 缺点/风险
| 项 | 量化影响 | 优先级 |
|---|---|---|
| **每次命令双重验证** | checkConnection(100-200ms) + getMyself(100-300ms) = 200-500ms 额外延迟 | P0 |
| **附件上传全量读入内存** | `fs.readFileSync` — 100MB 文件 ≈ 105MB 内存，有 OOM 风险 | P0 |
| **重试策略单薄** | 仅覆盖 ECONNRESET/ETIMEDOUT/socket，遗漏 429/502/503/504 | P0 |
| **批量操作阻塞** | Promise.all + 分批，一个慢请求阻塞整批 | P1 |
| **searchIssues 无自动分页** | total > maxResults 时不会自动获取剩余 | P1 |
| **中文文件名映射不完整** | 仅 ~80 个汉字，未映射的变 `_` | P2 |
| **超时配置僵化** | 所有操作统一 10s，大附件上传可能不够 | P2 |
| **配置重复读取** | 每次 readConfig() 都读文件，无内存缓存 | P2 |

## 四、汇总优先级排序

| 优先级 | 改进项 | 预期收益 |
|--------|--------|----------|
| **P0** | 登录验证缓存（5min 有效） | 每次命令快 200-500ms |
| **P0** | 抽取通用 `httpRequest<T>()` 方法 | 减少 ~200 行重复代码 |
| **P0** | 附件上传改 stream | 大文件安全，避免 OOM |
| **P0** | 增强重试策略（429/503 + 指数退避） | 可靠性显著提升 |
| **P1** | 补充 `create` 命令 | 功能完整性 |
| **P1** | 清理 `ws` 依赖，合并 cf-middleware | 代码简洁 |
| **P1** | 静态 import https，缓存 URL 对象 | 消除重复开销 |
| **P1** | me/projects 支持 JSON 输出 | AI 场景适配 |
| **P2** | shell completion（`j2c completion`） | 体验提升 |
| **P2** | 减少 `any`，加 response 类型 | 可维护性 |
| **P2** | pinyin 库替代硬编码汉字表 | 文件名可靠性 |
| **P2** | 差异化超时（上传 60s，搜索 30s） | 大文件场景 |
| **P2** | `--quiet` 模式 | CI 场景 |

## 五、本次变更摘要 (v1.1.3 → v1.1.4)

### 认证方式重构
- **旧方式**: 通过 Service Token 登录 Cloudflare Access 获取 `CF_Authorization` Cookie，每个请求带 Cookie
- **新方式**: 每个请求直接在 headers 中携带 `CF-Access-Client-Id` / `CF-Access-Client-Secret`，无需 Cookie 交换

### 变更文件
| 文件 | 改动 |
|---|---|
| `src/client/config.ts` | 删除 `cfCookie` 字段及相关函数，`isLoggedIn()` 改为检查 `hasCFServiceToken()` |
| `src/client/jira-client.ts` | `getCFHeaders()` 从返回 Cookie 改为返回 CF headers；新增 `getProjects()`、`getProjectIssueCounts()` |
| `src/client/cf-middleware.ts` | 注释掉旧的 `loginWithServiceToken` / `refreshCFCookie`，仅保留 CF 错误检测 |
| `src/cli/commands/setup.ts` | CLI 参数从 `--cf-auth` 改为 `--cf-client-id` / `--cf-client-secret` |
| `src/cli/index.ts` | 登录检查从 `hasCFCookie()` 改为 `hasCFServiceToken()`，更新所有提示文案 |
| `src/cli/commands/projects.ts` | **新增** 项目列表/详情命令 |
| `docs/jira2claw-cli.md` | 更新认证配置说明 |
| `README.md` | 更新认证配置说明 |
| `Jira CLI Development Specification.md` | 全面更新认证、项目结构、请求流程章节 |
